# Лабораторная работа: статическая маршрутизация в GNS3

## Описание проекта

В рамках лабораторной работы была создана виртуальная сеть из трёх маршрутизаторов Cisco 3745 в GNS3.

Цель работы — настроить статическую маршрутизацию между двумя IP-подсетями, проверить сетевую связность и изучить ICMP-трафик с помощью Wireshark.

## Топология сети

```text
R1 ---------------- R2 ---------------- R3
     10.10.10.0/24        10.10.20.0/24
```

## IP-адресация

| Маршрутизатор | Интерфейс       | IP-адрес      | Подсеть       |
| ------------- | --------------- | ------------- | ------------- |
| R1            | FastEthernet0/0 | 10.10.10.1/24 | 10.10.10.0/24 |
| R2            | FastEthernet0/0 | 10.10.10.2/24 | 10.10.10.0/24 |
| R2            | FastEthernet0/1 | 10.10.20.1/24 | 10.10.20.0/24 |
| R3            | FastEthernet0/1 | 10.10.20.2/24 | 10.10.20.0/24 |

## Настройка статической маршрутизации

Для обеспечения связи между подсетями на маршрутизаторах R1 и R3 были настроены статические маршруты.

**Маршрут на R1:**

```text
ip route 10.10.20.0 255.255.255.0 10.10.10.2
```

Этот маршрут указывает R1 передавать пакеты, предназначенные для сети `10.10.20.0/24`, через маршрутизатор R2 с адресом `10.10.10.2`.

**Маршрут на R3:**

```text
ip route 10.10.10.0 255.255.255.0 10.10.20.1
```

Этот маршрут обеспечивает обратный путь из сети R3 в сеть R1 через маршрутизатор R2.

Маршрутизатор R2 использует непосредственно подключённые сети для пересылки трафика между двумя подсетями.

## Проверка работоспособности

Для проверки конфигурации использовались следующие команды Cisco IOS:

* `show ip interface brief` — проверка IP-адресов и состояния интерфейсов.
* `show ip route` — просмотр таблицы маршрутизации.
* `show ip arp` — просмотр соответствий IP- и MAC-адресов.
* `ping` — проверка доступности узлов.
* `show running-config` — просмотр текущей конфигурации маршрутизатора.

**Результат:** проверка с помощью `ping` подтвердила связь между R1 (`10.10.10.1`) и R3 (`10.10.20.2`).

## Анализ трафика в Wireshark

Для изучения сетевого обмена используется Wireshark. Захват выполняется на соединении между R1 и R2.

Для отображения ICMP-пакетов применяется фильтр:

```text
icmp
```

В ходе анализа рассматриваются:

* **ICMP Echo Request** — запрос, отправляемый при выполнении `ping`.
* **ICMP Echo Reply** — ответ целевого устройства.
* IP-адреса источника и назначения в пакетах.
